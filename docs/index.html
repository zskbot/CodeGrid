Build from anywhere.
Stay in one workspace.

CodeGrid is a focused, mobile-first development workspace that runs in your browser. Edit files, use a live Bash shell, preview projects, and synchronize source code through Git and GitHub.

Get started View on GitHub

What is CodeGrid?

CodeGrid brings the essential parts of a development environment into one browser workspace. The browser provides the interface while the local Node.js server manages files, commands, previews, Git operations, and the GitHub connection.

Default workspace

~/CodeGrid/workspace · default server http://127.0.0.1:8899

Capabilities

The workspace is deliberately small: every major development operation stays close to the project you are working on.

01 · Shell
Live Web Shell

Persistent browser-connected Bash sessions for commands, package managers, scripts, and project workflows.

02 · Files
Explorer & Editor

Browse the workspace tree, open files, create files, edit source code, and persist UTF-8 content.

03 · Preview
Instant Preview

Serve workspace content directly through /preview/ and inspect the result without leaving the IDE.

04 · Source
Git & GitHub

Clone repositories, pull changes, stage and commit, push updates, and connect a GitHub repository.

Getting Started

CodeGrid runs as a Node.js application and exposes its workspace through a local browser interface.

Prerequisites

Node.js 18+

The current project targets Node.js 18 or newer.

Git + Bash

Git is required for source-control operations. Bash and script provide the live shell.

Install

Terminal 
git clone <your-codegrid-repository-url>
cd CodeGrid
npm install

Start CodeGrid

Terminal 
npm start

Then open http://127.0.0.1:8899. To use another port:

Terminal 
PORT=3000 npm start

Termux

The repository includes run-codegrid.sh, which manages the CodeGrid process and uses port 8899 by default.

Termux 
chmod +x run-codegrid.sh
./run-codegrid.sh

Project Structure

Architecture

CodeGrid uses a simple browser-to-server architecture. HTTP handles workspace operations while WebSocket provides the interactive shell.

Design principle

The browser is the workspace interface; the local server remains responsible for filesystem and process access.

Web Shell

The terminal is connected to the server through WebSocket. Commands execute inside the CodeGrid workspace rather than inside the browser itself.

Workspace
~/CodeGrid/workspace
Persistent connection

The browser maintains a WebSocket connection to the shell service.

Terminal output

ANSI-oriented shell output is normalized for the browser terminal surface.

Explorer & Editor

The Explorer maps the workspace filesystem into a recursive file tree. Selecting a file loads its content into the browser editor.

1
Browse

Load the recursive workspace tree.

2
Edit

Open a file and modify its plain-text content.

3
Save

Persist the updated UTF-8 content back into the workspace.

Preview

Workspace files can be served through the CodeGrid preview route. This makes it possible to inspect a web project directly from the IDE.

GET /preview/ Workspace preview root

Git & GitHub

CodeGrid treats Git as part of the workspace rather than a separate development tool. Repository operations can be initiated from the IDE.

Clone

Clone a repository into the current workspace.

Pull

Synchronize the workspace with its configured remote.

Commit

Stage workspace changes and create a Git commit.

Push

Send committed workspace changes to the configured remote.

GitHub Connection

CodeGrid uses GitHub's device authorization flow for browser-friendly authentication.

Configuration

Create .codegrid/github.env in the repository root:

.codegrid/github.env
GITHUB_CLIENT_ID=your_github_oauth_client_id
Keep credentials private.

The resulting token is stored locally. Never commit credentials or expose the .codegrid/ directory.

API Reference

The local CodeGrid server exposes JSON APIs for workspace, Git, and GitHub operations.

Method Endpoint Purpose
GET/api/healthServer and runtime status.
GET/api/workspaceWorkspace metadata.
GET/api/filesRecursive workspace file tree.
GET/api/file?path=…Read a workspace file.
PUT/api/fileSave a file.
DELETE/api/fileDelete a file or directory.
GET/api/github/statusGitHub connection status.
GET/api/github/reposList repositories.
POST/api/github/deviceStart device authorization.
POST/api/github/device/pollPoll authorization progress.
POST/api/github/linkConfigure the workspace remote.
POST/api/git/cloneClone a repository.
POST/api/git/pullPull remote changes.
POST/api/git/commitStage and commit changes.
POST/api/git/pushPush committed changes.

Health check

Terminal 
curl http://127.0.0.1:8899/api/health

Configuration

The server reads its runtime configuration from the process environment. The most useful setting for local development is the listening port.

Variable Example Purpose
PORT 3000 Changes the HTTP server port.
GITHUB_CLIENT_ID your_client_id GitHub device authorization client identifier.

Safety

CodeGrid is designed primarily for trusted local or private-network environments.

Do not expose the server directly to the public internet.

The terminal has the same permissions as the process running CodeGrid. Public deployment requires authentication, TLS, network controls, and additional hardening.

Review repositories before execution.

Cloning a repository and running its scripts gives those scripts the permissions available to the CodeGrid process.
